# InterviewVault 业务流程文档

版本：v1.0（2026-09-28，基于当前实现整理，与 PRD.md / PLAN.md 配套）
定位：本地优先的个人面试知识库——输入是面试录音/模拟面试，输出是问题卡片和复盘总结。

**三条铁律**（所有设计的裁判）：

1. **本地优先**：录音、转写稿、标注、卡片全部存本机（SQLite + 文件系统），离线可用，无后端
2. **用户自持 AI**：App 不内置 AI、不送额度；AI 请求从客户端直连用户自己配置的端点，App 只是"遥控器"
3. **数据自主**：全量 JSON + Markdown 随时导出带走，删除即真删

---

## 一、总体业务流程

```text
                        ┌──────────────────────────────┐
                        │            数据来源            │
                        │  ① App 内录音（锁屏可继续）     │
                        │  ② 导入音频文件                │
                        │  ③ 模拟面试（AI 出题，文字作答） │
                        └──────────┬───────────────────┘
                                   ↓
                    ①② 产生一条「面试记录」(draft) + 音频文件
                                   ↓
              本地转写（whisper.cpp，模型 base/small 按需下载）
                                   ↓
                     状态 draft → transcribed（逐字稿分段）
                                   ↓
        逐字稿页：读分段 → 打标签（面试官/我/问题/亮点/失误/待改进/自定义）
                                   ↓
                     首次标注入库 → 状态 transcribed → annotated
                                   ↓
              打「问题」标签的段落 → 自动生成问题卡片（可再编辑）
                                   ↓
      ┌───────────────┬───────────────┬────────────────┐
      ↓               ↓               ↓                ↓
   翻卡复习        面试总结页        按日汇总         导出/备份
 (reviewCount)  (聚合视图,非AI)   (按日期分组)   (Markdown/JSON)
```

模拟面试（③）跳过录音和转写：AI 直接出题 → 文字作答 → AI 流式反馈 →
问答直接落库为逐字稿分段 + 卡片（状态即 transcribed、无音频），与真实面试在
逐字稿页/卡片/总结页里**统一管理**。

## 二、数据模型速览

六张表（SQLite，drift 管理，外键级联删除）：

| 表 | 内容 | 要点 |
|---|---|---|
| interviews | 面试记录 | 公司/岗位/轮次/日期/时长/音频路径/**status 状态机** |
| transcript_segments | 逐字稿分段 | 起止秒 + 文本 + speaker（interviewer/candidate/空） |
| annotations | 标注 | 挂在某分段上：标签 + 可选笔记 |
| flashcards | 问题卡片 | 正面/背面/AI 参考/标签(JSON)/来源时间锚/复习计数 |
| ai_configs | AI 服务商配置 | provider/模型名/baseUrl/是否激活，**不存 Key** |
| tags | 标签定义 | 预置 5 个系统标签 + 用户自定义 |

**面试状态机（只进不退）**：

```text
draft（草稿，仅有音频）
  → transcribed（已转写；模拟面试直接落在此状态）
  → annotated（首次标注后）
  → summarized（导出过 Markdown 总结后）
```

## 三、功能详解

### 1. 录音（数据来源①）

**用户流程**：底栏中央 ⏺ → 录音页 → 显示实时波形 + 计时 → 可暂停/继续 →
停止 → 保存命名 → 生成一条 draft 面试记录。

**实现**：

- `record` 插件采集，电平流（0..1，容量 28）直接渲染成波形条
- **锁屏后台录音**：Android 前台服务（`foregroundServiceType="microphone"` +
  常驻通知），防止系统杀进程导致录音中断——这是 P0 需求
- 音频存应用私有目录 `recordings/`；删除面试记录时同步删音频文件（删除即真删）

### 2. 音频导入（数据来源②）

**用户流程**：首页「导入音频」→ 系统文件选择器（支持 mp3/wav/m4a/aac/ogg）→
**格式确认页**（显示文件名/格式/大小/时长）→ 确认 → 复制进应用私有目录 →
draft 面试记录。

**实现**：`file_picker` 选文件 → just_audio 探测时长（探测失败则界面降级不显示）
→ 复制文件到库目录。副本归 App 托管，随记录删除而删除。

### 3. 本地转写（语音 → 文字）

**用户流程**：进入 draft 面试详情（逐字稿页）→ 首次会引导下载转写模型
（base 约 142MB / small 约 466MB，WiFi 提示）→ 选模型 → 「开始转写」→
进度条 → 完成后逐字稿分段列表出现。

**实现**：

- **whisper.cpp**（FFI 集成，推理跑在后台 isolate，UI 不卡）
- 模型管理：dio 下载 + 进度流，主源失败自动切国内镜像，magic 头与体积校验，
  原子落位；可在「我的 → 转写模型管理」删除
- 转写结果按时间戳切分为**逐字稿分段**（segment）落库，状态翻转为 transcribed
- 转写完可**再次转写**覆盖旧稿（如换用 small 模型）

> 说明：当前版本仅支持**本地转写**（不出设备，隐私最大化）；云端 ASR 在 PRD
> 中是可选项，未实现。

**转写后的人工整理**（都在逐字稿页完成）：

- 点分段 → **编辑校正**文字（识别错的字）
- 点说话人 chip → 手动循环标记：未标记 → 面试官 → 我（P0 为手动，P1 才自动区分）

### 4. 标注系统

**用户流程**：在逐字稿分段上点标注 → 弹层选择标签（可写复盘笔记）→
分段上出现标签 chip；点 chip 跳转播放对应位置；长按 chip 编辑/删除；
顶部标签筛选条可按标签过滤分段。

**实现**：

- 标签 = 5 个预置系统标签（**问题 / 回答 / 亮点 / 失误 / 待改进**）+ 用户自定义
  标签（重名拦截，可长按删除）
- 每条标注可挂一段**复盘笔记**
- 首次标注入库时状态翻转 transcribed → annotated（只进不退）
- 播放跳转基于音频回放抽象（seek 到分段起点）

### 5. 问题卡片（核心资产）⭐

**这是"自动生成还是自己填"的关键**——卡片内容分四块，来源各不相同：

| 卡片内容 | 来源 | 生成方式 |
|---|---|---|
| **正面：问题** | 逐字稿 | **自动**：取打了「问题」标签的那个分段的原话 |
| **背面：我的回答** | 逐字稿 | **自动**：拼接问题段之后**连续的"我"的分段**（遇到下一段面试官发言或下一个问题段即停） |
| **背面：AI 参考思路** | AI | **可选生成**：点"生成参考"后由你配置的 AI 流式生成（分点、≤200 字）；中断保留已生成部分；未配置 Key 给引导文案 |
| **标签** | 标注 | **自动**：等于来源分段上的全部标注标签（与回顾页筛选打通） |

此外**每张卡都可在卡片详情页手动编辑**（正面/背面均有编辑对话框），AI 参考
也可重生成。所以是"自动打底 + 人工可改"。

**生成时机与幂等**：在标注弹层把某段标为「问题」并选择"存为卡片"时生成；
同一场面试 + 同一来源段 + 同一问题文本 → 更新已有卡而不是新建（重复生成不
会产生脏数据，且已生成的 AI 参考会保留）。

**卡片与录音的关系**：卡片带 `source_start_time / source_end_time` 锚点，
来源卡显示时间，可跳回面试逐字稿查看上下文。

**复习计数**：翻卡页点「已复习」会 review_count+1 并记录时间（间隔重复 SM-2
是 P1 规划，当前为简单复习列表）。

### 6. 模拟面试（数据来源③，AI 全程参与）

**用户流程**：首页「模拟面试」→ 未配置 AI Key 会先弹引导去配置 →
配置页：**岗位（必填）+ 简历（粘贴文字或导入 PDF）+ JD（可选）** →
AI 生成 5 道面试题 → 逐题文字作答 → 每题提交后 AI 流式返回
**【优点】【不足】【改进建议】** → 下一题/跳过 → 全部完成。

**实现**：

- 出题与反馈都通过用户自己的 AI（chatCompletionStream 流式，逐字渲染）
- 中断容错：流式反馈中途退出，**已收到的内容保留**并随会话落库
- 防误退：作答有进度时返回弹确认框
- **会话落库**：整场模拟面试写成一条面试记录（状态 transcribed、无音频），
  每题写一对 Q/A 逐字稿分段（面试官/我），每题一张卡片
  （问题/我的回答/AI 参考=该题反馈，标签=[问题]）——与真实面试统一进
  逐字稿页、卡片库、总结页
- 简历 PDF 用**纯 Dart** 解析提取文字（不依赖 Google 服务，国内可用）；
  扫描件/加密件无法提取时引导改用"粘贴文字"

### 7. 面试总结页（W4 新增）

**用户流程**：面试详情页右上角 → 面试总结页：面试信息卡 + 标注统计
（按标签计数）+ 问题卡片列表（可点进卡片详情）+ 录音概要（有无音频/
分段数/转写字数/时长）→ 右上角导出本场 Markdown。

**实现**：**纯数据聚合视图，没有 AI 总结**——所有内容都来自已落库的
标注和卡片。从草稿状态进不来（无可总结内容）；导出成功后状态推进为
summarized。

### 8. 按日汇总（W4 新增）

首页「今日汇总」→ 按面试日期倒序分组：每日一张卡显示**场数 + 累计时长**，
当日面试行（公司·岗位）点进详情。同样是数据聚合，无 AI。

### 9. 翻卡复习

**用户流程**：回顾 Tab →（可先按标签筛选）「开始回顾」→ 逐张翻卡：
正面=问题+标签，点击 3D 翻面=我的回答+AI 参考 → 「已复习」（计数+1 并推进）
或「跳过」（不计数）→ 最后一张后显示本轮统计 → 返回。

**实现**： Transform 3D 翻转（外层转角 + 背面预转 180° 保证文字不镜像），
复习计数走 markReviewed。筛选条件决定复习哪些卡。

### 10. 导出与数据管理（W4 完整落地）

| 功能 | 说明 |
|---|---|
| 单场 Markdown 导出 | 严格按 PRD 模板生成（面试信息 + 逐题：问题/我的回答/标注/复盘笔记/AI 参考），**格式被快照测试锁定**，改动=破坏性变更。写入 `exports/` 目录后调系统分享 |
| 全量 JSON 导出 | 六表全量 + schema_version（结构稳定承诺），pretty JSON，可用于备份或二次处理 |
| 全量 Markdown 导出 | 所有面试的单场文稿按日期升序合并为一个 bundle 文件 |
| 数据删除 | 单条：面试列表滑动删除（含音频清理）；**全部**：二次确认后级联清库 + 删音频 + 删 AI 配置与 Key + 删自定义标签（系统标签保留） |
| 隐私政策/用户协议 | 「我的」内全文 |

### 11. AI 配置与 Key 安全

**用户流程**：我的 → AI 服务配置 → 选服务商（OpenAI/DeepSeek/Kimi/通义/
Claude/自定义）→ 填模型名 + BaseURL + API Key → 「连接测试」（发一次真实
请求验证）→ 保存并激活。可配置多个、独占激活一个。

**实现与安全红线**：

- **Key 只存 flutter_secure_storage**（Android Keystore），绝不进 SQLite、
  日志、异常堆栈、导出文件
- 网络层只在请求 host == 用户配置的 baseUrl 时注入 Authorization
- 日志拦截器对全部 header 脱敏
- 仓库中不出现任何真实 Key；用户可随时删除 Key

## 四、AI 参与点汇总

AI 不是常驻能力，只有 4 个点会调 AI，且**全部走用户自己的 Key/端点**：

| # | 场景 | 输入 | 输出 | 未配置 Key 时 |
|---|---|---|---|---|
| 1 | 模拟面试出题 | 岗位+简历+JD | 5 道题（JSON，容错解析、截前 5） | 首页入口弹引导去配置 |
| 2 | 模拟面试逐题反馈 | 题目+我的作答 | 优点/不足/改进建议（流式） | 同上 |
| 3 | 卡片 AI 参考思路 | 问题+我的回答 | 参考答案思路（流式，≤200 字） | 卡片详情页显示引导文案 |
| 4 | 连接测试 | 配置信息 | 成功/失败 | —（本来就是配置页的事） |

录音、转写、标注、卡片主体、总结页、按日汇总、导出——**全部不依赖 AI**，
断网可用（转写需已下载模型）。

## 五、"自动 vs 手动"边界总表

| 内容 | 自动/手动 | 说明 |
|---|---|---|
| 面试记录创建 | 自动 | 录音保存/导入确认时生成 |
| 逐字稿 | 自动 | whisper.cpp 本地转写 |
| 逐字稿文字校正 | 手动 | 分段编辑框修正识别错误 |
| 说话人标记（面试官/我） | 手动 | 点 chip 循环切换（自动区分是 P1） |
| 标签与笔记 | 手动 | 用户在逐字稿上标注 |
| 卡片正面（问题） | 自动 | 来自「问题」标注的分段原话 |
| 卡片背面（我的回答） | 自动 | 拼接问题段后的"我"的连续分段 |
| 卡片 AI 参考思路 | 半自动 | 用户点击才生成，可重生成，可编辑 |
| 卡片标签 | 自动 | 继承来源分段的标注标签 |
| 卡片内容修改 | 手动 | 详情页编辑对话框 |
| 模拟面试出题/反馈 | 自动（AI） | 用户只写作答 |
| 总结页/按日汇总 | 自动（聚合） | 纯数据视图，无 AI 总结 |
| Markdown/JSON 导出 | 自动（模板） | 格式锁定，一键生成 |
| 数据删除 | 手动 | 单条滑动删 / 全部二次确认删 |

## 六、平台与边界（明确不做的）

- MVP **仅 Android**（代码保持双端兼容；iOS 延后用 Codemagic 补）
- 无账号系统、无云同步、无社区、无支付、无内置 AI/免费额度
- 无视频面试、无招聘端、无遥测上报
- 图片简历 OCR 依赖 GMS，国内不可靠——P0 引导粘贴文字
- 国内安卓无 GMS：全栈不依赖 Google 服务组件
